# 玄学能力与体系压力测试 v0.2.1

2026-10-23 · 形成可辨认、有完整推导的人物能力画像，再将画像放入具体实践任务。按下列框架充分展开分析，再写成有主线的散文报告。

## 本版负责什么

本 skill 是统计塔罗的专题报告入口。已有抽样、统计计算、牌义资料和四元素本体继续使用；玄学能力题的论断顺序与成稿由本入口负责，不再并行执行原统计 SOP 的解读阶段或复用旧报告结论。一般统计塔罗问题仍走原 skill。

将原统计 skill 的目录记作 `BASE_SKILL`，本目录记作 `REPORT_SKILL`。按实际安装解析，不根据客户端名改写路径：

1. 优先采用用户明确给出的原统计 skill 路径；没有显式路径时，检查本 skill 的兄弟目录 `statistical-tarot-elemental-reading/`。
2. 若仍位于仓库的 `addons/mystic-talent-report/` 内，检查上两级目录。任何候选都须确认 `SKILL.md` 的 `name` 是 `statistical-tarot-elemental-reading`，且有 `data/tarot/` 与 `references/`，再记作 `BASE_SKILL`。
3. 找不到有效依赖时，说明需要安装 [原统计 skill](https://github.com/Kico-Tachagemofet/statistical-tarot-elemental-reading) 或提供路径，不静默换方法。

将牌库目录记作 `CARD_DATA = BASE_SKILL/data/tarot/`。Markdown 链接相对当前文档；`BASE_SKILL/...`、`CARD_DATA/...` 与 `REPORT_SKILL/...` 是上述解析后的路径。领域资料随本包位于 `references/domains/`，不依赖私有案例或实验目录。

## 流程

明确问题与材料 → 完整读牌 → 按框架展开各元素 → 分析跨元素作用并合议状态 → 形成能力画像 → 进入具体体系 → 成稿与核对。

各步骤列出需要读取的框架及本步产出；分析材料持续记入同一份 `AUDIT.md`，供下一步调用。

## 步骤 0：明确问题与材料

确定本次研究谁的哪项能力、用于什么任务，以及怎样算完成；理解一次经验、向别人解释、完成作品和长期服务各有自己的完成标准。记录材料范围、牌义版本与开关、输出位置，以及本轮是否使用用户经验。

优先使用已有 `protocol.json`、`statistics.json` 和五堆数据卡。只有用户明确要求新测且尚无抽样时，才由原统计 skill 完成一次抽取，再转回本流程；随机组件开始后保留已有回执，部分或不确定结果不重抽替换。

涉及玄学能力、灵视、灵感或内在经验时，先读 [四组功能框架](references/seership-frameworks.md)，明确本题要考察的输入回应、内部体验、加工和连接领会。此处确定观察问题，步骤 2–3 根据牌义形成具体判断。

**本步产出：**本次问题、分析对象、完成标准与资料状态。

## 步骤 1：完整读牌

**框架与资料：**读取 [牌义与占星校准](references/card-astrology.md)，按本次 `card_id` 读取 `CARD_DATA/{pips,courts,atu}.json` 或数据卡中的相关完整条目。资料为摘要时按其精度使用，需要进一步含义时查对应原文。

作者包开启时，按 `BASE_SKILL/references/meaning-pack.md` 加载已选包的 `manifest.json` 与有关大牌完整正文，记录单牌版本及 `meaning_use`（正文短引＋用于哪项判断），与 Book T 属性分层使用。关闭时使用本次 Book T 材料；明确开启而缺包或缺正文时停止相应加载步骤。牌义源与开关在本次分析中固定。合成测试直接使用给定的完整内联语义。

分别读火、水、风、土、大阿卡纳五堆。对相关牌充分展开核心动作、作用对象、条件分支和限制，再以源质、占星及宫廷复合元素细化；将偏多、偏少与已知基线记在对应形态旁。大牌有明确元素标签时并入对应元素，未指定时保留为语义材料，参与功能与全场判断。

### 统计读法

沿用已有次数、z、分段和校正结果。1000 次时，小牌每张预期约 14.29、大牌约 9.09；单牌 `|z|<1` 为基线、`1≤|z|<2` 为普通偏离、`|z|≥2` 为极端候选。普通偏离细化形态，极端候选提供重点分析位置；Holm 校正作为记录保留。

五堆总量按相对口径读取：N 次时每堆预期 `N/5`，标准差 `sqrt(N×0.2×0.8)`；1000 次约 12.65。最高与最低相差超过一个标准差时，最高标相对偏多、最低标相对偏少，保留并列者，其余为中间堆；否则五堆持平。总量背景与堆内单牌集中分别解释。

正逆比例作方向探针：结合具体牌义判断动作受压、内折、位置交换或表达变化。正逆、旬星星座尊贵和 Book T 条件分支分别处理；本统计盘的条件分支由全场支持／牵制收束。能力与表现由后续功能分析判断。

**本步产出：**五堆的具体牌义材料、属性与统计强调程度，供单元素展开使用。

## 步骤 2：按框架展开各元素

**框架：**完整读取 `BASE_SKILL/references/` 中对应的元素卡 `fire.md`、`water.md`、`air.md`、`earth.md`，结合 `properties.md` 的性质框架，以及本报告的 [元素应用口径](references/element-application.md) 和 [论断与关系 §1–3](references/inference-contract.md)。原方法卡提供元素本体与观察角度，本专题应用口径指导怎样落到个人功能。

每个元素分别形成**无序形态谱**，充分展开并比较各形态的具体内容、统计强调程度、适用对象与范围，以及彼此的共存、差别与张力。按下面的关系把牌义转成可用的功能判断：

> **具体内容／动作 → 以怎样的性质运行 → 本题中处理什么、产生什么 → 支持条件与限制。**

冷热干湿、方向、空间、轻重与层次用于解释具体动作。说明同一功能有哪些实现方式、同一元素能承担哪些功能；此步把单元素的形态与功能展开充分，整场状态交由步骤 3 合议。

读取 [体验、转译与制作](references/experience-processing.md)，按本题需要分辨体验、理解、表达、制作及持续工作的具体节点。相关题目结合四组功能框架：在这里展开水自身的内容与体验形态，并准备火水、水土、风与火风的作用候选。

**本步产出：**四个元素的无序形态谱、具体功能及适用条件，连同待合议的跨元素候选。

## 步骤 3：分析跨元素作用并合议状态

**框架：**完整读取 `BASE_SKILL/references/relations.md`、`combinations.md`，结合 [论断与关系 §4–5](references/inference-contract.md) 判断本盘实际成立的共创、两极、因果或背景关系。

充分展开两端的动作与牌义依据、共同对象或具体传递关系，以及作用后的表现。因果候选以不同主元素之间有依据的具体作用成立；同元素材料继续用于形态、范围与张力的比较。实际先后按另有的时间材料说明；多条关系分别保留各自的对象与作用依据。

综合这些关系，判断每个元素在全场中如何获得支持、改变或受到牵制，收束其状态及整场的具体表现。关系尚未建立处保留已有形态与功能，说明未定连接。

相关题目在此完成四组功能判断：K1 火水输入与回应、K2 水的内部体验、K3 水土加工、K4 风的连接及火风领会。各项写清具体运作、支持到的层次及未定细项；体验、加工、输入与领会分别收口。

**本步产出：**有效关系及其依据、全场中的元素状态，以及相关功能支持到的具体层次，交给画像层综合。

## 步骤 4：形成并固定能力画像

**框架：**按 [论断与关系 §6–7](references/inference-contract.md)，综合步骤 2–3 的功能、关系与全场状态。比较同一功能的不同实现方式，处理支持与相反材料；有张力的判断按任务、内容和操作方式分清适用范围。

将**支持／相反材料／未覆盖**与统计强调程度分别记录。功能可用性、是否突出、感官模态、稳定度、准确性与来源各自判断；低强调用于限制对应形态的主导性，未知项保留在它所属的层次。

形成约 3–5 条有辨识度的能力主线 A1…，数量随材料调整。七模块用于检查覆盖：直觉整合、灵感生成、辨识收束、象征理解、转译表达、定向施行、持修调节。商业轴分别判断定位、表达、包装、交付、组织和经营。

接收矩阵细化已有功能：按材料登记梦境、视觉、听觉、身体、非言语领会、外部符号材料、主动观想与对象互动，再分自发／诱导、保留、辨识、转译、边界与退出。用户经验单列来源；商业与实践能力各自形成判断。

每条 A 保留**判断＋处理对象／适用任务＋牌义与功能依据＋支持状态及相反材料＋相关未定项**，涉及关系时引用对应记录。将综合后的画像记作 `profile_frozen`，供领域分析使用；新校准或证据修正另记画像版本和改动依据。

**本步产出：**可直接用于领域测试的固定能力画像及其依据、范围和条件。

## 步骤 5：进入具体体系

**框架与资料：**读取 [领域任务压力测试](references/domain-pressure.md) 的十四体系索引。沿用用户已选体系；希望勾选时在画像完成后提供列表；自动选择时取画像最有依据的 3–5 项，记录理由。完整读取所选 `references/domains/` 主卡，再读 [宫位与喜乐亲和](references/field-affinity.md)。

按具体支线及入门、深入或服务角色选取任务节点，展开：**画像中的哪项功能 → 怎样用于这项工作 → 哪个衔接有支持、相反材料或未覆盖 → 对工作方式和结果有什么影响。** 每个体系写出自己的实际判断，有明确缺口时写清通过条件。

领域任务链提供实践要求，按支线可合并、循环或省略节点。灵视分支接续前面的功能及体验／加工判断；宫位与喜乐用于细化任务场景。会改变路径的未定条件同时进入结论。

**本步产出：**各体系有区别的工作方式、长处、条件及实际后果，均可回查固定画像。

## 步骤 6：成稿与核对

**框架：**读取 [报告写法](references/report-writing.md)，按其中的交付前核对完成成稿。

`REPORT.md` 先写能力怎样运作，再写领域任务后果；正文呈现已形成的判断及会改变其含义的条件，每节留一行简短依据。所有面向个人的灵视判断以“你可能……”或“你或许……”开句，承载具体范围；统计、原文、定义与支持状态照实写，标题使用主题。

`AUDIT.md` 保存从材料、形态谱、功能、跨元素关系与全场状态，到固定画像和领域应用的可回查依据，以及相关未决项。

**本步产出：**将两份成品写入本轮指定的新输出目录；按用户要求修订既有稿。正式归档或对外发布遵循所在项目的授权规则，原抽样保持不变。
